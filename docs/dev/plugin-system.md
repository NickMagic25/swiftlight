# Mac plugin implementation

The [user guide](../plugins.md) specifies the YAML schema, configuration and execution behavior. macOS exclusivity is intentional: desktop adapters are guarded by `#if os(macOS)`, and the Xcode plugin product has a Mac framework filter. No mobile lifecycle invokes plugins.

`Sources/shared/SwiftlightPlugins/PluginManifest.swift` owns pure value models, YAML parsing, field validation and exact trigger matching. The isolated package product uses exact-pinned Yams 6.2.2. A libyaml event preflight rejects anchors/aliases, explicit tags, multiple documents, excessive depth/nodes and invalid syntax before Yams builds its recursive tree. Schema validation rejects unknown/duplicate keys and bounded inputs. Parser excerpts and configured values do not appear in error messages.

`Sources/desktop/Plugins/PluginManager.swift` owns MainActor settings publication, saved reviewed manifests and per-session snapshots. Import and refresh never execute code. Approval applies to the cached manifest; refresh disables it before reading the source. Secret configuration is stored under a plugin-specific login-Keychain service, outside the JSON configuration, using the same nonsynchronizing local policy as host identity storage. Keychain calls run off the main actor. Secret hydration and pending configuration saves prevent admission from using incomplete configuration.

`ClientModel` captures the attempted host/app identity and a random session ID before asynchronous connection work. `PluginStreamLifecycle` admits exactly one start when decoded output moves that generation into streaming. It retires the captured context before teardown can suspend. After transport stop and decoder close, the manager queues end hooks from the original enabled-plugin snapshot. Failed pre-output attempts and stale callbacks cannot produce hooks. Reconnect retains native teardown serialization and queues the end before beginning another connection.

`PluginJobRunner` uses a dedicated serial utility worker, a bounded FIFO and a cancellation generation protected by `NSCondition`. Admission does not wait for script completion. `posix_spawn` atomically creates a process group and closes inherited file descriptors. Scripts run from a unique owner-only temporary directory, receive a minimal environment and literal field values, and have stdin/stdout/stderr connected to `/dev/null`. Swift uses a job-local compiler module cache. Timeout/cancellation terminates the process group and reaps the child; normal exit also kills remaining descendants in that group. Arbitrary trusted code can deliberately detach into another process group; this runner is resource management, not a security boundary for hostile native code. App Sandbox supplies the platform boundary.

Normal shutdown gives the worker a maximum five-second grace period, then cancels work. Stream teardown itself never waits for plugins. No extra stream surface, per-frame publication, decoder callback work or plugin data in diagnostic exports is introduced. Start admission occurs in the existing low-rate statistics update that detects decoded output. No no-regression latency claim is implied; live stream and actual integration checks remain independent.

Both app packaging paths include the Yams and libyaml MIT notices from `App/Licenses/`. The existing Mac sandbox, signing and stream trust policy remain in force. Installed external interpreters, LaunchServices/VirtualHere behavior, USB permissions, Keychain access in the signed app and App Store distribution need separate runtime acceptance.

## Verification

Use `SwiftlightPluginsTests` for real YAML and field validation, `PluginLifecycleTests` for generation/identity/exact-once semantics, and plugin runtime tests in `SwiftlightAppTests` for cached persistence, literal environment values, queue bounds, timeouts, descendants and session snapshots. Run the primary signed Xcode Mac build, inspect Settings → Plugins, and run `scripts/validate-ci.sh` for the broader shared-module/dependency gate. Packaging fixtures exercise bundled-notice requirements; they do not establish signing or runtime access.

Apple guidance consulted on 2026-10-04: [Settings](https://developer.apple.com/design/human-interface-guidelines/settings), [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility), [SwiftUI Form](https://developer.apple.com/documentation/swiftui/form) and [Foundation Process](https://developer.apple.com/documentation/foundation/process). The settings window uses native grouped forms and panes, preserves the standard Settings entry point, restores the selected pane, labels configuration controls and uses semantic colors. Child execution retains the app's sandbox.
