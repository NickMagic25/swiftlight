# Swiftlight common-c patches

`Dependencies/moonlight-common-c` is the real, pristine Git submodule. Its revision and nested ENet/nanors revisions are pinned in `Dependencies/versions.json`. `scripts/prepare-common-c.py` archives committed source, verifies each pin and clean tracked content, then applies this explicit `series` into ignored `Sources/shared/CStreamBridge/vendor/common-c`. Build and native validation entry points invoke preparation. Edit these patches rather than the generated source or upstream checkout.

The application currently selects upstream `62e066388f1a1b133e0bee947b9a374311a3354b`. The first three patches were extracted and audited against the earlier local Qt reference `874ac9548f1bd6f095ef2b435c42cdde460e7821`; all three pass `git apply --check` against both pins. The three newer upstream commits change only `RtpVideoQueue.c` and `VideoDepacketizer.c` (12 insertions, 6 deletions) and do not overlap those first three patches. The fourth patch was added against the selected `62e0663` source to observe its RTP outcomes. Their upstream frame-loss/recovery improvements remain intact.

| Patch | Files | Purpose and required caller contract |
|---|---|---|
| `0001-serialize-cancellation-and-termination.patch` | `src/Connection.c`, `src/Limelight-internal.h` | Use an atomic interruption flag and atomic-exchange termination arbitration; keep the single termination callback thread joinable until teardown. Stop first joins media/control callers and then termination delivery before platform cleanup. App callbacks enqueue lifecycle work and must never invoke stop inline. |
| `0002-expose-darwin-clock-epoch.patch` | `src/Platform.c` | Expose the immutable Darwin `CLOCK_UPTIME_RAW` epoch after platform initialization. The bridge converts common-c relative microseconds into the decoder's absolute monotonic nanoseconds, with less than one microsecond of quantization. |
| `0003-expose-bound-video-socket-address.patch` | `src/VideoStream.c` | Read `getsockname` on the actual video socket while the bridge's API gate prevents concurrent stop/close. This is route evidence, not an inference from a separate global network monitor. |
| `0004-count-confirmed-rtp-frame-outcomes.patch` | `src/RtpVideoQueue.c`, `src/RtpVideoQueue.h`, `src/VideoStream.c` | Count completed RTP reassemblies and irrecoverable network frame skips with per-queue atomics, reset on initialization. A read-only accessor is called under the bridge start/stop gate. Speculative notifications, local decoder queue overflow, and recovery filtering do not inflate network loss. |
| `0005-support-pyrowave-transport.patch` | `src/Limelight.h`, `src/Limelight-internal.h`, `src/ControlStream.c`, `src/RtspConnection.c`, `src/SdpGenerator.c`, `src/Video.h`, `src/VideoDepacketizer.c`, `src/RtpVideoQueue.c`, `src/RtpVideoQueue.h` | Negotiate the four explicit PyroWave profiles and record framing; pass independent payloads through without NAL processing; deliver recoverable partial frames with lost-packet and record-start boundaries plus the critical-packet count. Reject an explicit incompatible bitstream revision or unsupported selected profile. Capture synchronized HDR control values with each decode unit. |
| `0006-trace-frame-transport-milestones.patch` | `src/Limelight.h`, `src/RtpVideoQueue.h`, `src/RtpVideoQueue.c`, `src/VideoDepacketizer.c` | Carry decisive accepted packet receipt, final FEC readiness, actual queue-offer time and partial-frame status with each decode unit. Preserve recovery, queue admission and ownership behavior. |

The fifth patch ports only the PyroWave protocol changes from [Nonary's common-c fork at `927eba9639f3c9b5037ab45fc0d6486e2a19b39f`](https://github.com/Nonary/moonlight-common-c/commit/927eba9639f3c9b5037ab45fc0d6486e2a19b39f), originating in `57def66`, `5862e83`, and `927eba9`. It preserves the selected upstream's newer recovery fixes and the existing four patches. Local adaptations bound the partial-packet lookup, reject malformed short frame headers, match SDP token attributes on exact lines, reject explicit revision/profile mismatches, and count delivered partial frames as confirmed network loss. Missing bitstream advertisements remain permitted for legacy hosts, with their compatibility unverified until decode. Payload boundaries must remain intact through the bridge for critical-packet validation and record resynchronization.

The existing RTP/FEC/encryption path remains authoritative; PyroWave's partial recovery extends it only for explicitly selected PyroWave streams. Each missing data payload becomes a zero-filled buffer when enough metadata remains; a missing first packet or entire FEC block still drops that frame. These buffers contain no video decoder implementation. Existing licenses and notices remain present in the generated source. The patches may be proposed upstream separately; no upstream submission is implied.

PyroWave has no encoded color metadata. The scoped control-state gate therefore publishes HDR active state and optional metadata together, and snapshots them into each decode unit at assembly. Its critical section holds only bounded value copies; decoding, callbacks and packet parsing run outside it. The official HDR getters use the same gate. This prevents a Swift event-delivery delay or a newer control update from recoloring an already queued frame. The protocol carries no frame ID in HDR control messages, so a snapshot still represents the latest reported state at assembly during a transition.

The sixth patch samples userspace RTP-queue entry for each incoming packet and records only the final accepted packet that makes a complete frame recoverable, including parity. This is not a kernel/wire arrival measurement and still includes receiver scheduling and earlier-block FEC/order work between packet entries. Partial frames have no last-required-packet timestamp. Final FEC readiness follows all reconstruction or lost-packet synthesis and ordering, before whole-frame depacketization. Queue offer follows decode-unit creation, HDR snapshot and keyframe bookkeeping. All milestones travel with the same frame and use the existing common-c clock. Native cases cover out-of-order final arrival, parity reconstruction, delayed final blocks, duplicates, partial synthesis, and preservation through local AU replacement; live timing acceptance remains separate.

To prepare and verify idempotently:

```sh
git submodule update --init --recursive
python3 scripts/prepare-common-c.py
python3 scripts/prepare-common-c.py
scripts/validate-transport-native.sh
SWIFTLIGHT_SANITIZERS=thread scripts/validate-transport-native.sh
```

Before the submodule migration, the owned native suite passed ASan/UBSan and TSan for exact frame completion, concurrent audio transfer, keyboard wire normalization/release, clock/permissions, deterministic cancellation phases and callback retirement. The final clean verification report records the rerun against the selected submodule revision; do not treat an earlier vendored-tree result as validation of a different upstream revision.

The telemetry addition is documented and validated in [stream statistics](../../docs/stream-statistics.md). The standalone native harness executes the actual patched RTP packet paths with no-host callbacks, including real Reed-Solomon recovery, speculative versus confirmed loss, and concurrent atomic reads.

PyroWave's no-host native cases also exercise single- and multi-block partial delivery, rejection when the first packet or a whole block is missing, preservation of all payload boundaries and critical count, zeroing lost payloads, exact profile intersection, incompatible advertised revisions, and the actual serialized SDP for every profile. HDR cases retain the metadata of a queued HDR frame after control switches to SDR, validate raw units through the bridge, and race 100,000 state publications with atomic snapshot reads. These checks do not establish live host interoperability or decoding performance.
